# 10 · 简单复杂度分析

> 对应练习：`ex09_binary_search.cpp`（把 O(n) 干成 O(log n)）、`ex10_enum_greedy.cpp`（同一道题的暴力版和优化版摆在一起）、`ex14_contest_drill.cpp`（把「能不能过」写成代码）
> 目标：看数据范围就能判断"这个思路能不能过"，并在写代码前避掉溢出与内存超限。

---

## 1. 怎么算自己代码的复杂度

规则只有三条：

1. **看最内层执行次数**。`for i<n` 套 `for j<n` → n²；`for i<n` 套 `for j<i` → n²/2，仍是 O(n²)。
2. **相加取最大，相乘全保留**。`O(n + n²) = O(n²)`；`O(n × log n)` 要写全。
3. **别忽略"看不见"的代价**：`sort` 是 n log n、`map` 插入是 log n、`vector` 中间 erase 是 n、`string` 拼接在循环里可能退化、`endl` 每次 flush。

---

## 2. 量级对照表（时限 1 秒的粗略标尺）

| 复杂度 | n 上限经验值 | 典型算法 |
|---|---|---|
| O(1) / O(log n) | 任意 | 公式、快速幂 |
| O(n) | 1e7 ~ 1e8 | 线性扫、前缀和、双指针、计数排序 |
| O(n log n) | 1e6 ~ 2e6 | sort、二分套排序、归并、树状数组 |
| O(n√n) | 1e5 ~ 2e5 | 分块、试除判质数 |
| O(n²) | **3000 ~ 5000** | 双重枚举、区间 DP、朴素 LIS、冒泡 |
| O(n² log n) | ≤ 1000 | 排序套双重循环 |
| O(n³) | 300 ~ 500 | Floyd、三维 DP |
| O(2ⁿ · n) | n ≤ 20 | 状压 DP |
| O(n!) | n ≤ 8 ~ 11 | 全排列搜索、N 皇后 |

**读题第一件事是看数据范围**，它基本就告诉你该用什么复杂度。看到 `n ≤ 20` 就该想到状压或搜索；看到 `n ≤ 1e5` 就说明需要 O(n log n) 或更优；`n ≤ 5000` 则 O(n²) 是允许的上限。

## 3. 本机实测数据

同一份基准程序（本仓库外的临时文件，best-of-5 取最小值）在 g++ 16.1.0（Windows / MinGW-w64）下分别用 `-O2` 和 `-O0` 跑：

| 操作 | 基本运算量 | 耗时（-O2） | 未优化（-O0） |
|---|---|---|---|
| 前缀和扫一遍 | 1e6 | 0.4 ms | 5.4 ms |
| `sort` 100 万个 `int` | ≈ 2e7 次比较 | 60.7 ms | 110 ms |
| 二维数组按行遍历 5000×5000 | 2.5e7 | 5.8 ms | 82 ms |
| 埃氏筛到 1e7（含写内存） | ≈ 3e7 次标记 | 25.3 ms | 92 ms |
| 朴素 LIS，n = 1e4 | 5e7 次比较 | 102 ms | 497 ms |
| 1e8 次空循环 | 1e8 | 0.0 ms（整个被优化掉了） | 48 ms |

结论（都是上面这张表能直接指出来的）：

- **1 秒的预算怎么花**：顺序扫描类（前缀和）1e8 次大约 40 ms 起，但数组一大就撞内存墙；带比较和分支的（LIS）5e7 次要 102 ms。所以 **1e8 次是稳的，3e8 次要赌常数，1e9 次基本超时**。
- **`-O2` 与 `-O0` 的差距没有固定倍数**：循环体越简单差得越多——前缀和差 14 倍、二维遍历差 14 倍、LIS 差 4.9 倍；而 `sort` 只差 1.8 倍，因为它的时间花在**访存**上，不在指令数上。所以「本地跑得慢」未必是算法问题，但也别指望 `-O2` 救你：量级错了，多少倍都不够。
- 反过来也别迷信：上表里 5e7 次比较用 102 ms 很轻松，可 n 从 1e4 提到 3e4，比较次数按 `n²/2` 就是 **4.5e8 次**，线性外推已接近 1 秒，实际因为缓存 miss 更多只会更差——直接超时。

**估算法**：把 n 代进你的复杂度算出总次数，再和 1e8 比。算出来超过 3e8 就该换思路；在 1e8 附近要看常数（`map`、`vector<vector<>>` 的缓存不友好、`endl` 都会把常数放大 3~10 倍）。

## 4. 内存也要算

| 限制 | 换算 |
|---|---|
| 128 MB | ≈ 3.3e7 个 `int` ≈ 1.6e7 个 `long long` |
| 256 MB | ≈ 6.7e7 个 `int` |
| 512 MB | ≈ 1.3e8 个 `int` |

高频翻车点：

```cpp
int dp[5000][5000];              // 1e7 × 4B = 40MB，勉强
int dp[20000][20000];            // 1.6GB ← 直接 MLE，必须换滚动数组或压缩状态
vector<vector<int>> a(n, vector<int>(m));   // n=1e5, m=1e5 想都别想
```

**滚动数组**是二维 DP 的第一招：如果 `dp[i][j]` 只依赖 `dp[i-1][...]`，就只保留两行（甚至一行 + 控制遍历方向）。见第 13 章背包部分。

另外 `vector<vector<int>>` 每行有 24 字节的额外开销（指针+size+capacity），n = 1e6 行时光这个就 24MB——行数极多时用一维 `vector<int>` 手动算下标。

## 5. 溢出：复杂度之外的隐形杀手

```cpp
int n = 1e5;                       // 合法输入
long long s = 0;
for (int i = 0; i < n; i++) s += a[i];        // 若 a[i] 也是 1e5 → s 最大 1e10，超 int
int area = w * h;                  // w,h = 1e5 → 1e10 溢出，且是「先按 int 乘」
```

**最阴的情况**：`long long area = w * h;` —— 右边两个 `int` 先相乘溢出，**再**赋给 `long long`，救不回来。要写 `1LL * w * h` 或 `long long(w) * h`。

判断要不要 `long long` 的口诀：**只要出现"求和、求积、两个大数相乘、路径计数、子集计数"，先按 `long long` 写**。取模题要在每步运算后 `% MOD`，且 `(a * b) % MOD` 里 a、b 都得是 `long long`。

`-Wall -Wextra` 抓不到溢出，`-fsanitize=undefined` 能抓到**有符号溢出**并指出行号——`make san/exNN` 就是干这个的。

## 6. 常数的坑（量级对但依然超时）

| 行为 | 代价 | 替代 |
|---|---|---|
| 循环里 `endl` | 每次 flush，1e6 次可达数百 ms | `'\n'` |
| `cin` 不加速 | 1e6 个数慢 3~5 倍 | `ios::sync_with_stdio(false); cin.tie(nullptr);` |
| 比较函数不用 `const&` | sort 里拷贝 n log n 次对象 | `[](const T& a, const T& b)` |
| 循环内 `string +=` 超长内容 | 反复 realloc | `reserve` 或攒进 `ostringstream` |
| `map` 当哈希用 | 每次操作多一个 log | `unordered_map`（注意最坏退化） |
| `vector` 中间 `erase` | 每次 O(n) | 攒着批量处理，或换 `list`/标记删除 |
| 二维 `vector` 按列遍历 | 缓存不友好 | 改成按行遍历，或一维展开 |

## 7. 三个练习题（先心算，再跑代码验证）

1. `n ≤ 1e5`，求所有无序对 `|a[i]-a[j]|` 之和 → 双重循环是 5e9 次，**过不了**。排序后用 `Σ a[i]·(2i-n+1)` 变成 O(n log n)。
2. `n ≤ 1e6`，m ≤ 1e6 次"区间加"，最后输出整个数组 → 直接模拟 1e12 次，**过不了**。差分：O(n + m)。
3. `n ≤ 20`，问"选若干个能否凑出 target" → 枚举所有子集 2²⁰ ≈ 1e6，**能过**。

这三条覆盖了"暴力为什么不行"和"换思路后为什么行"的典型判断路径。第 1 条去 `ex10`（数对计数的暴力版和双指针版放在一起，能直接看出差距），第 2 条去 `ex08`（差分），第 3 条去 `ex11`（子集/组合枚举 + 剪枝）。
