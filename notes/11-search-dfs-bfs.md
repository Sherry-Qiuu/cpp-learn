# 11 · 搜索入门：DFS 与 BFS

> 对应练习：`ex11_dfs_backtrack.cpp`、`ex12_bfs_containers.cpp`
> 搜索 = 在"状态图"上按某种顺序走一遍。所有暴力枚举、迷宫最短路、连通块问题都是它。

---

## 1. 先把问题抽象成状态图

三个问题问清楚，搜索代码就写出来了：

| 问题 | 例子（全排列） | 例子（迷宫） |
|---|---|---|
| **状态**是什么？ | 已选的序列 + 用过哪些数 | 当前坐标 (r, c) |
| **初始状态**？ | 空序列 | 入口 (0, 0) |
| **转移**（一步能做什么）？ | 选一个没用过的数 | 上下左右走一格（不撞墙） |
| **目标/终止**？ | 序列长度 = n | 到达出口 |

状态总数 × 每个状态的转移数 = 搜索空间大小，也就是复杂度。全排列是 n!，迷宫是 n×m。

---

## 2. DFS：一条路走到黑 + 回溯

**结构**：递归。走到不能走就退回上一步，换个分支继续。

### 模板一：枚举型（要回溯）

```cpp
void dfs(vector<int>& pool, vector<int>& path, vector<char>& used) {
    if ((int)path.size() == (int)pool.size()) {   // ① 到达完整状态：记录答案
        for (int x : path) cout << x;
        cout << " ";
        return;
    }
    for (int i = 0; i < (int)pool.size(); i++) {
        if (used[i]) continue;                    // ② 剪枝：这个分支不能走
        used[i] = 1;  path.push_back(pool[i]);    // ③ 做选择
        dfs(pool, path, used);                    // ④ 深入
        path.pop_back();  used[i] = 0;            // ⑤ 撤销选择 ← 回溯的灵魂
    }
}
```

`ex11` 实测：`{1,2,3}` 输出 `123 132 213 231 312 321`，正好 6 = 3! 个。

**"做选择 → 递归 → 撤销选择"这三行必须紧挨着成对出现。** 忘写第 ⑤ 步是最典型的错误：症状是"只输出了第一个排列 123，后面什么都没有"。

### 模板二：遍历型（不需要回溯）

图/网格连通块遍历，走到的格子标记一下就行，不需要撤销：

```cpp
void floodFill(int r, int c) {
    if (r < 0 || r >= n || c < 0 || c >= m) return;    // 越界
    if (vis[r][c] || g[r][c] == '#') return;           // 已访问 / 障碍
    vis[r][c] = 1;                                     // 标记（进函数就标）
    for (int k = 0; k < 4; k++) floodFill(r + dr[k], c + dc[k]);
}
```

## 3. BFS：一层层往外扩

**结构**：队列。先进先出保证"先被发现的节点一定比后发现的距离近"，于是——

> **边权全为 1 时，BFS 第一次到达目标的路径就是最短路径。** 这是 BFS 存在的唯一理由（DFS 不能保证最短）。

```cpp
vector<vector<int>> dist(n, vector<int>(m, -1));   // -1 兼作"未访问"
queue<pair<int,int>> q;
dist[0][0] = 0;  q.push({0, 0});
while (!q.empty()) {
    auto [r, c] = q.front(); q.pop();              // C++17 结构化绑定
    for (int k = 0; k < 4; k++) {
        int nr = r + dr[k], nc = c + dc[k];
        if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;    // 越界剪枝
        if (g[nr][nc] == '#' || dist[nr][nc] != -1) continue;    // 墙 / 已访问
        dist[nr][nc] = dist[r][c] + 1;             // ★ 入队时就标记
        q.push({nr, nc});
    }
}
cout << dist[n-1][m-1] << "\n";                    // -1 表示不可达
```

`ex12` 实测：5×7 迷宫，从 (0,0) 到 (4,6) 最短 **10** 步。

**"入队时标记"而不是"出队时标记"**：同一个节点可能被多个邻居同时发现，出队才标记会让它重复入队好几次，队列内存爆炸、复杂度退化。这是 BFS 唯一必须记牢的细节。

**分层遍历**（求"最少轮次""腐烂的橘子"这类题）：

```cpp
int steps = 0;
while (!q.empty()) {
    int sz = (int)q.size();           // ★ 当前层的节点数
    while (sz--) { /* 处理并扩展 */ }
    steps++;                          // 处理完一层 = 走了一步
}
```

## 4. DFS vs BFS 怎么选

| | DFS | BFS |
|---|---|---|
| 数据结构 | 递归栈（或手写 `stack`） | `queue` |
| 内存 | O(深度) | O(最宽一层的节点数) ← 可能很大 |
| 能否给最短路径 | **不能**（无权图也一样） | **能**（边权为 1） |
| 适合 | 枚举所有方案、连通性、拓扑、回溯构造具体方案 | 最短路、最少步数、"同时扩散" |
| 风险 | 深度太大爆栈 | 状态太多内存爆 |

经验：**求"最少几步"→ BFS；求"所有方案/一个可行方案"→ DFS**。边权不为 1 的最短路要用 Dijkstra（`priority_queue` 版 BFS），见第 12 章末尾。

## 5. 剪枝：让搜索从"跑不完"变成"秒出"

**① 可行性剪枝**——这个分支根本走不通，别进去。

```cpp
if (used[i]) continue;                     // 重复用同一个元素
if (r < 0 || r >= n) continue;             // 越界
if (cur + w[i] > capacity) continue;       // 已经超过限制，再往下只会更差
```

**② 最优性剪枝**——能走到，但再怎么努力也不如已有答案。

```cpp
if (depth >= best) return;                 // 当前已经比已知最优差
if (cur + 乐观估计剩余 >= best) return;     // 估价函数（A* 思想的雏形）
```

**③ 重复状态剪枝 / 记忆化**——同一个状态算过一次就不算第二次。

```cpp
if (seen[state]) return;                   // visited 数组就是最朴素的形态
```

这一条威力最大：一个状态空间只有 n×m 的迷宫，不标记会走指数级路径，标记后是 O(n·m)。**当"记忆化 + 递归 + 求最值/方案数"三个条件凑齐，你就已经写出了 DP**（第 13 章）。

**④ 排序剪枝 / 去重**：枚举组合时先排序，`if (i > start && a[i] == a[i-1]) continue;` 跳过重复分支（"组合总和 II"类题目的关键）。

## 6. 搜索的复杂度怎么估

`搜索空间大小 × 每个节点的处理代价`。全排列 O(n·n!)（n! 个叶子，每个打印要 O(n)）；子集 O(n·2ⁿ)；迷宫 O(n·m)。

对照第 10 章的表：**n ≤ 11 能全排列，n ≤ 20 能枚举子集**，再大就必须靠剪枝或换 DP。

## 7. 五个必踩过的坑

1. **忘回溯**（`used[i] = 0`）→ 只出一组解。
2. **visited 忘记标 / 标错时机** → DFS 无限递归爆栈，BFS 队列撑爆。
3. **越界判断放在访问之后**：`if (g[nr][nc] == '#' && ...)` 里 `nr` 可能已经越界。**顺序永远是：先判越界，再访问数组。**
4. **递归深度超限**：迷宫 1000×1000 的 DFS 深度可到 1e6 → 本机 4.3 万层就崩。要么改 BFS，要么改迭代栈，要么把大数组挪到全局。
5. **多组数据忘清空全局状态**（`vis`、`ans`、`path`）→ 只第一组对。这是 OJ 上"本地对提交错"的头号原因。
