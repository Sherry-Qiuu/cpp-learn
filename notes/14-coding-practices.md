## 1. 边界条件：动手前先把这几行写进脑子

| 边界 | 典型症状 | 处理办法 |
|---|---|---|
| `n = 0` | 读入后数组空，`a[0]` 越界 | 特判，或让循环自然跳过 |
| `n = 1` | 相邻比较 `a[i-1]`、`a[i+1]` 越界 | 检查首尾元素的处理 |
| 全部相同 / 全部逆序 | 答案 0 或 1，最值初始化成 0 就错 | `mx = INT_MIN`、`mn = INT_MAX` |
| 含负数 | `mx = 0` 起步导致答案错；`abs` 后溢出 | 最值用第一个元素初始化 |
| 值域上限 | 求和/乘积爆 `int` | 一律 `long long` |
| 首尾输出格式 | 行末多空格、少换行 | 用 `if (i) cout << ' ';` 模式 |
| 多组数据 | 第二组开始全错 | 每组开始时重置全局数组/`ans` |
| 下标换算 | 题目 1-based，代码 0-based | 数组开 `n+1`，全程用 1-based |

三条最值初始化的铁律：

```cpp
int mx = INT_MIN;                  // 而不是 0
int mn = INT_MAX;
int mx = a[0];                     // 更好的写法：拿第一个元素初始化
long long best = -1;               // 表示"还没有合法答案"，用 -1 而不是 0
```

## 2. 溢出与取模

```cpp
long long s = 0;
for (int i = 0; i < n; i++) s += a[i];              // a[i] 是 int 也没事，s 是 long long

int area = w * h;                                    // ★ 错：先按 int 乘，已溢出
long long area = w * h;                              // ★ 还是错：右边先算完
long long area = 1LL * w * h;                        // 对
long long area = (long long)w * h;                   // 对，且意图更清楚
```

取模题的两条规矩：

1. **每步运算后立刻 `% MOD`**，不要等最后。
2. **减法取模可能得负数**：`x = (a - b) % MOD;` 当 `a < b` 时是负的，要写 `x = (a - b % MOD + MOD) % MOD;`。这个 bug 编译器不会报，样例常常也测不出来。

## 3. 调试：从"瞪眼看"到"五分钟定位"

### 第一层：让编译器帮你查

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -g -O0 t.cpp -o build/t.exe    # 警告全开，一个都别放
make san/ex05                                                          # ASan + UBSan 运行
```

`-fsanitize=address,undefined` 会直接打印：

```
==1234==ERROR: AddressSanitizer: stack-buffer-overflow on address ...
    #0 main ex05.cpp:42
```

**"哪一行、读了哪个越界的地址"一次说清**。程序行为诡异（结果随机、段错误、死循环）时，第一件事就是加 sanitizer 重跑，而不是继续改代码试试运气。

注意：**MinGW 的 ASan 支持不完整**（缺运行时 dll 时会报 `Unable to execute file`）。抓不到的话退而求其次：只开 `-fsanitize=undefined`，或者靠 `-Wall -Wextra` + 打印定位。

### 第二层：打印，但打印得有价值

```cpp
cerr << "i=" << i << " dp[i]=" << dp[i] << "\n";   // ★ 用 cerr，不是 cout
```

`cerr` **不写进 stdout**，所以：本地照常看，交上去也不会污染答案（OJ 忽略 stderr），不用删干净。这是最重要的一条调试习惯。

打印要打印**中间量**而不是最终结果：把题面样例的每一步手算出来，找到**第一个和手算不一致的位置**，bug 就在那一小段。逐个 print 是二分查找，别一次打十个变量。

想看输出里的空格和换行：`cout << "DBG[" << s << "]\n";` 用方括号夹住，行尾空格立刻现形。

### 第三层：断点单步

VS Code 里打开文件，`F5`（已配好 gdb 和 `preLaunchTask`），`F10` 逐行、`F11` 进入函数、监视窗口看变量。适合查**复杂指针/递归状态**；查"某个变量在第几步变错"时用打印更快。

### 第四层：对拍（找反例，而不是找 bug）

怀疑贪心/DP 错了，写一个 20 行的暴力 + 一个随机数据生成器，跑 1000 组，看哪一组两个程序输出不同：

```bash
# 思路示意：gen 造数据，a.exe 是正解（暴力），b.exe 是你的优化解
for i in $(seq 1 1000); do
  ./gen.exe $i > data.txt
  ./brute.exe  < data.txt > o1.txt
  ./fast.exe   < data.txt > o2.txt
  cmp -s o1.txt o2.txt || { echo "第 $i 组不一致"; cp data.txt bad.txt; break; }
done
```

`bad.txt` 就是那个反例，往往小到一眼能看出问题。**"想不出反例"不等于"贪心是对的"**，对拍才是。

## 4. 竞赛/作业代码的标准骨架

```cpp
#include <bits/stdc++.h>          // 一把梭头文件（竞赛可用，工程别用）
using namespace std;

const int MAXN = 100005;
const long long INF = 4e18;

int a[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    if (!(cin >> n)) return 0;     // 读入失败直接退出，防止空输入
    for (int i = 1; i <= n; i++) cin >> a[i];

    // ---- 核心逻辑 ----

    return 0;
}
```

要点：

- `bits/stdc++.h` 在洛谷/Codeforces 上都能用，能省掉十几行 include；换到别的编译器（MSVC）会失败，此时老老实实逐个 include。
- `if (!(cin >> n)) return 0;` 处理"空输入"，OJ 上偶尔能救命。
- **先把输入读进来、把主流程骨架跑通（哪怕逻辑是假的），再填细节**。一上来就写最难的转移方程，容易在没跑通的代码里调不出东西。
- 写完立刻用题面样例跑一次；过了以后**自己造 3 组数据**：最小规模（n=1）、最大规模、以及"全相同/全逆序"这种极端分布。

## 5. 提交前 30 秒检查清单

```
[ ] 变量名和题意对得上（l/r、i/j 没有写反）
[ ] long long：涉及求和、乘法、计数
[ ] 数组开得够大，且 +1 / +2 的位置留了（差分要 n+2）
[ ] 下标从 0 还是 1，和读入一致
[ ] 循环边界 < 还是 <=，最后一段处理没漏
[ ] 输出：只有答案，没有 "请输入" 之类的提示文字
[ ] 输出：换行结尾、行内空格数量符合要求
[ ] 多组数据：全局数组和 ans 每组都重置
[ ] 本地用样例跑过，并且造过一组边界数据
```

**"本地对、提交错"的三大原因**：多组数据没重置、`int` 溢出的大样例、输出格式（多打了解释文字或用 `endl` 混了空格）。

## 6. 代码风格（会让调试快很多）

1. **有意义的变量名**：`left_bound`、`max_profit`，别用 `a b c tmp flag2`。出 bug 时你要在 50 个变量里猜哪个是区间端点。
2. **函数拆分**：一个函数只做一件事。超过 60 行的 `main` 说明你需要函数了（也让递归/DP 的单步验证更容易）。
3. **常量化**：`MOD`、`INF`、`MAXN` 用 `const`/`constexpr`，不要满屏魔法数字。
4. **缩进一致**（4 空格或 2 空格，别混），花括号风格统一。
5. **删掉注释掉的死代码**再提交，版本管理交给 git。
6. **警告清零**：把 `-Wall -Wextra` 的输出当错误处理。`unused variable` 常常意味着"你以为赋值了其实没用上"。

## 7. 时间分配（做题的节奏）

```
读题 5 分钟：把输入格式、输出格式、数据范围、样例各抄一遍
想 10 分钟：先估复杂度 → 定思路；想不出就先写暴力拿部分分
写 20 分钟：骨架 → 读入 → 核心 → 输出，每步都编译一次（不要一口气写完才编译）
查 10 分钟：样例 + 自造边界 + sanitizer
```

**每写 10 行编译一次**。攒 100 行再第一次编译，你会同时面对 30 条报错和真正的逻辑 bug，效率极低。
